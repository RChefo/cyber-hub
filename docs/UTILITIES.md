# Security utilities

Security Utilities (sidebar) groups local tools (encoders, parsers, formatters) and network tools. This page describes the tools added with the platform expansion. The backend code is in `src-tauri/src/sectools/` and `src-tauri/src/commands/sectools.rs`; the views are in `src/modules/utilities/tools/AssessmentTools.tsx`.

| Tool | Contacts | Rules |
|---|---|---|
| HTTP request builder | the URL's host | **Project required; active scope gate** on the URL host and on any `Host` header (another virtual host is another target). The project must be active. Methods GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS; at most 50 headers (no line breaks, `Content-Length`/`Transfer-Encoding` set automatically); body ≤ 1 MB; response read ≤ 2 MB; 20 s time limit; redirects followed only when asked, at most 5, each checked against the scope before it is sent; untrusted certificates only with an explicit switch. A host name is resolved once and refused if it points at a private, loopback, link-local or reserved address that is not itself in the scope; the request then connects only to the checked addresses (DNS-rebinding protection). A response that is not HTTP is reported as such. **Repeater:** a raw request pasted from a proxy or the browser (with an optional target, otherwise the `Host` header over HTTPS), resend from the session history, comparison of two responses (status, timing, size, changed headers, line diff of the bodies) and *Copy as cURL*; a request opened from a project's API inventory arrives prefilled. Every send goes through the same checks. The history stays in memory until Cyber Hub closes and is never saved, because requests can carry credentials; the activity log records method, URL (credentials redacted) and status. |
| TLS analyzer | the host and port | **Project required; active scope gate**, with the same resolved-address check as the HTTP request builder. Up to three handshakes (TLS 1.2+1.3, 1.3 only, 1.2 only), nothing sent after them. Reports the negotiated protocol and cipher, ALPN, the certificate chain (subject, issuer, validity, names, key, signature, SHA-256), and trust against the system roots. Issues are graded critical, warning or note. TLS 1.0/1.1 cannot be tested (rustls does not implement them) and the report says so. The certificate is recorded as a project asset (`certificate`, keyed by fingerprint). |
| DNS intelligence | the system resolver | **Passive scope gate:** internal and single-label names are refused, and project exclusions apply when a project is chosen. The tool queries A, AAAA, CNAME, NS, MX, SOA, TXT, CAA, `_dmarc`, ten common DKIM selectors and DNSKEY. It assesses SPF (`+all`, missing or weak `all`, duplicate records, more than 10 lookups), DMARC (missing, `p=none`, partial `pct`, no reports), DKIM, CAA and DNSSEC. Domains without MX get advice, not warnings. |
| Port & service reference | nothing | Offline reference of common ports: service, typical risks, checks. It also lists where recorded project services expose the port. |
| Subdomain monitor | public sources only | Shows new and missing names across a project's passive discovery runs, with certainty. *Monitor on a schedule* creates or updates a passive-only workflow ([WORKFLOWS.md](WORKFLOWS.md)). |
| IOC extractor (Analysis) | nothing | Extracts URLs, domains, IPv4 and IPv6 addresses, e-mail addresses, MD5/SHA-1/SHA-256/SHA-512 hashes and CVE IDs from pasted text (≤ 2 MB, ≤ 5,000 per kind). It first refangs `hxxp`, `[.]`, `(.)`, `{.}`, `[dot]`, `[:]`, `[://]`, `[@]` and `[at]`. File names such as `report.pdf` or `payload.exe` are not taken for domains (common file extensions are excluded as top-level domains, except those that are real top-level domains: com, zip, mov, pl, sh, md, rs, py). Patterns are bounded so long pasted inputs stay fast (tested on hostile 40,000-character runs). IPv6 candidates are validated, so times and MAC addresses are not reported. Output is defanged (CyberChef style) or plain; IPs, domains, URLs and hashes open in Threat Intel for a lookup. The transform workbench has *Defang indicators* and *Refang indicators* operations. Code: `src/modules/utilities/lib/ioc.ts`. |
| Container & Kubernetes checks | nothing | Checks pasted text, a file or a folder chosen in a native dialog (`sectools/containers.rs`); nothing is contacted, built or run. **Dockerfiles** (multi-stage aware): root user (the USER of the final stage, inherited through `FROM <stage>`; distroless and nonroot bases are trusted), unpinned base images, scripts piped into a shell, certificate checks turned off, chmod 777, sudo, ADD with a URL or for plain files, secrets in ENV and ARG, an exposed SSH port, no HEALTHCHECK; each with its line. **Compose files** (merge keys applied): privileged, host network/PID/IPC/user namespaces, the runtime socket and sensitive host paths mounted, powerful capabilities, seccomp/AppArmor/SELinux turned off, host devices, secrets in `environment`, databases and the Docker API published on every interface, unpinned images, a root user. **Kubernetes manifests** (Pod, Deployment, StatefulSet, DaemonSet, ReplicaSet, Job, CronJob, and List): the Pod Security Standards' baseline (privileged, host namespaces, hostPath, host ports, capabilities, /proc mount, seccomp Unconfined) and restricted (privilege escalation, non-root, seccomp profile, dropped capabilities) controls, plus a writable root file system, missing limits, unpinned images, literal secrets in `env`, cluster-admin bindings and Services exposed outside the cluster. **RBAC** (`sectools/containers_rbac.rs`), after the Kubernetes RBAC good practices: Roles and ClusterRoles are checked for the ways to more privileges that page lists (wildcards, reading Secrets, the escalate, bind and impersonate verbs, `nodes/proxy`, approving certificate requests, `serviceaccounts/token`, admission webhook configurations, creating PersistentVolumes or workloads, `pods/exec` and `pods/attach`, changing namespaces), with matching as the API server does it (`*`, `*/exec`, API groups; get on named Secrets only is fine). RoleBindings and ClusterRoleBindings are resolved to their roles, in the same file or, in a folder, in any file (the built-in admin, edit, view and cluster-admin roles are known), and reported when they reach many identities at once: anonymous users (any role), every authenticated user, every service account (of a namespace) or a namespace's default service account (dangerous roles). The API server's own `system:` bindings are left alone. References name the Pod Security Standards control, the CIS Docker Benchmark recommendation or the RBAC good practice. A folder is searched to 50,000 entries and 2,000 configuration files of at most 5 MB, without following links and without .git, node_modules, vendor, target and build folders; Helm templates are reported as needing `helm template` first. Selected issues can be recorded as findings in a chosen project, once each. |
| Cloud & IaC checks | nothing | Checks pasted text, a file or a folder chosen in a native dialog (`sectools/iac.rs`, `sectools/iam.rs`); no cloud account is contacted and nothing is deployed. **Inputs**: Terraform HCL (`.tf`, parsed with hcl-rs; `jsonencode` of literal objects and heredoc policies are read, `data "aws_iam_policy_document"` blocks become policies), Terraform JSON configuration and `terraform show -json` plans (planned values, child modules, rendered policy documents), CloudFormation templates (JSON or YAML; short-form tags such as `!Ref` are kept as plain values), single IAM policies, AWS CLI output (`get-policy-version`, `get-role`) and `aws iam get-account-authorization-details` (users, groups, roles, inline policies, default versions of customer managed policies, URL-encoded documents). **AWS resources**: S3 public ACLs and Block Public Access settings, security groups open to 0.0.0.0/0 or ::/0 (all ports critical; SSH, RDP, Telnet, WinRM and 16 database or data service ports high; other ports low; 80 and 443 alone are fine), public or unencrypted RDS and Redshift databases, IMDSv1 on instances and launch templates, unencrypted EBS volumes, AdministratorAccess attached, access keys created in Terraform or CloudFormation, CloudTrail logging, regions and log validation, KMS key rotation, Lambda function URLs without authentication and permissions for any principal, load balancers serving plain HTTP, and EKS endpoints open to the internet. **IAM policies** (one document at a time, as written; Deny statements without conditions are honoured, effective permissions across policies, boundaries and SCPs are not computed): full administrator access, service-wide wildcards for sensitive services, NotAction and NotResource, the 28 privilege-escalation methods catalogued by Rhino Security Labs (each needs all of its actions), assuming any role, resource and trust policies open to any principal without a narrowing condition, web identity trust (GitHub Actions) without a subject condition, and cross-account trust without an external ID (low; same-account trust in an account export is not reported). Values written as references, variables or functions are not resolved and not reported; a setting that is missing counts as its documented default. References name the CIS AWS Foundations Benchmark recommendation or the AWS guidance. Issues can be recorded as findings, once each. |
| Packet capture triage | nothing | Reads a pcap or pcapng file chosen in a native dialog (`sectools/pcap.rs`), streamed, up to 2 GB and five million packets; nothing is contacted or replayed. Link types: Ethernet (with VLAN tags), Linux cooked capture v1 and v2, raw IP and BSD loopback; IPv4 and IPv6 (extension headers, first fragments), TCP and UDP. It lists hosts, conversations, DNS names with their answers, HTTP requests (method, host, path without the query, User-Agent), TLS server names from ClientHello messages, and credentials sent in cleartext (HTTP Basic, FTP and POP3 USER/PASS, IMAP LOGIN, SMTP AUTH PLAIN) with the user name and the **length** of the secret only. Issues: cleartext credentials (high), cleartext protocols such as Telnet, FTP, POP3, IMAP, SNMP, LDAP and VNC (medium), and plain HTTP (low); they can be recorded as findings in a chosen project. Tables are capped at 500 rows. |
| Log triage | nothing | Reads pasted lines (up to 20 MB) or a log file (up to 1 GB, line by line) (`sectools/logs.rs`). **Web access logs** (Apache and Nginx, combined or common format): SQL injection, cross-site scripting, path traversal and command injection payloads in the decoded request (double encoding included), Log4Shell lookups anywhere in the line, Shellshock headers, known scanner User-Agents, sensitive files answered with 200 (high) or only probed, clients with 100 or more 404 responses, and 20 or more failed or repeated logins. **OpenSSH authentication logs**: password guessing per client (high from 100 failures), a login after five or more failures from the same client (high), root logins, password logins, and many unknown user names. Matches are attempts, not proof of a compromise. Example lines go through the credential redaction used for tool output; detections can be recorded as findings in a chosen project. **Windows event logs (EVTX)**, recognised by their signature whatever the file name: read without Windows APIs by Cyber Hub's own reader (`sectools/evtx.rs`, after Microsoft's MS-EVEN6: chunks, records, binary XML with templates, substitutions and nested fragments; bounded, damaged chunks and records are skipped and counted). It was checked against the independent python-evtx parser on 60,081 events (this machine's System and PowerShell logs and 17 EVTX-ATTACK-SAMPLES files): the same events, IDs, channels, providers, computers and field names; values differ only in presentation. 35 detections (`sectools/winevents.rs`), with their MITRE ATT&CK technique where one fits: cleared event logs (1102, 104) and audit policy changes; password guessing and spraying (4625, from 10 failures or 5 accounts per source) and a logon after five or more failures; Remote Desktop logons; explicit credentials used by a web or database server process (web shells) or for another host (4648); user accounts created, including names ending in $; members added to privileged groups (by well-known SID or name); services installed with a command line (7045, 4697, and service ImagePath values in Sysmon 13), services or drivers in writable folders, and other services (low); scheduled tasks (4698) that run a shell or a file in a writable folder; process creations (4688 with the parent resolved from the creator's process ID on older Windows, Sysmon 1) with encoded PowerShell, download commands, signed-binary proxy execution, credential dumping, shadow copy deletion, log clearing, account commands or a WMI parent; PowerShell script blocks (4104) that dump credentials, disable AMSI, load code in memory or download, and obfuscated ones; LSASS opened with memory-reading rights (Sysmon 10); DCSync by accounts that are not domain controllers (4662); Kerberoasting (RC4 service tickets, 4769) and AS-REP roasting (4768); Microsoft Defender detections and disabled protection; Run keys (Sysmon 13); remote threads (Sysmon 8). The report lists the most frequent event IDs with their meaning and the computers. Detections are leads, not proof; they are not Sigma rules, and live logs on this computer are not read (export them with `wevtutil epl`). Findings carry the technique in their details and as a tag. |
| Secrets scanner | nothing | Scans pasted text, a file or a folder chosen in a native dialog. It looks for private keys, cloud and SaaS tokens (AWS, GitHub, GitLab, Slack, Stripe, Google, Anthropic, OpenAI, SendGrid, Twilio), JWTs, credentials in URLs, and password or secret assignments (with an entropy threshold, placeholders ignored). Symbolic links are not followed, and dependency and version-control folders are skipped. Limits: 20,000 files, 5 MB per file (binary files skipped), 5,000 findings. Matches are returned masked; the full value never leaves the backend and nothing is stored. |

The existing DNS lookup and HTTP header analyzer are unchanged. The wordlist manager (Wordlists page) covers the wordlist part of the expansion request: indexing by reference or managed copy, folder scans, preview, export and safe delete.

The scanner commands are named `leak_scan_*`: an existing test refuses any IPC command whose name contains "secret", so that no command can read or change stored credentials.
